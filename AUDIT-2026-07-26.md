research-mode semantics), 1 adversarial reviewer of the in-flight 7-fix diff, 1 test-writer,
and 5 opus-tier adversarial reviewers (gad-kit orchestration, gad-kit research integrity,

**How to read this.** `CONFIRMED` = traced to a contradicting source line, reproduced against a
real temp repo, or observed by executing the code. `SUSPECTED` = reasoned but not reproduced.
`pre-existing` = present at `claude-relay@cdd0f7c` / `gad-kit@f1862fe`. `introduced` = added by the
uncommitted 7-fix round. Every finding below carries at least one independent confirmation;
findings that only one agent asserted and no one could reproduce are in §7.

## §6 — Cross-cutting structural recommendations

1. **Make the mechanical soft-gates actually mechanical.** C2 and D15 are the same defect: a
   predicate over a field the graded agent chose. Pass `green`, `confirmedFindings` and
   `criteriaMet/criteriaTotal` into the consolidate prompt with the same `MUST return BLOCKED`
   imperative the live-verification signals already get, and stop blocking on a self-assigned
   `severity`.
2. **Test enforcement, not prompt strings.** D17 and the meta-gate assessment converge: four
   cheap scenarios would have caught C1, C2, C4 and C7 — red-verify + a `COMMITTED`-returning
   consolidator must not return COMMITTED; N failing generations must start ≤ maxGens children;
   `GREEN + confirmedFindings` must spawn a fix; child args must carry `models`/`tiers`. And
   `judge_metrics.py` needs unit tests at all (NaN, n=1, n=2, missing floor, path-absent).
3. **Keep the contract test.** The test-writer's `InstalledGadKitArgContractTests` — a skip-gated,
   read-only assertion of the arg keys against the *installed* plugin — is the structural answer to
   the original compatibility question. Extend it to the status enums and artifact paths.
4. **One spender, enforced.** E2 needs a real answer: a shared lock file both systems honour, or
   documentation that says pick one. Today nothing prevents double-spend on a shared quota.
5. **Notify on death.** B12, B21, B24 and B29 mean the failure modes most likely to happen are the
   ones the operator is least likely to hear about. A top-level `except Exception` that notifies
   before re-raising, plus a heartbeat the monitor can read, would close most of it.
6. **Fail loud, not reassuring.** D1, D2, E6 and E8 all share a shape: the error path prints a
   *success-flavoured* message. A skipped judge should be RED, not "non-training generation".

### E1 — SETTLED. The ladder never worked, and there is a third defect nobody predicted.

Live-tested against `claude` **2.1.220** with gad-kit **2.0.0** installed:

- `claude -p "/gad-run $REPO --max 1"` — the literal form in `bin/gad-cron-tick.sh:69` and
  `bin/gad-fleet-tick.sh:139` — prints `Unknown command: /gad-run` and **exits 0**. The stream-json
  shows a synthetic pre-model rejection: `model:"<synthetic>"`, `num_turns:0`, zero tokens, 12ms.
  Reproduced three times, deterministic. CONFIRMED.
- **New defect the audit missed:** the CLI registers the command as **`gad-kit:gad-run`**
  (namespaced). The scripts invoke the bare name. Adding `--dangerously-skip-permissions` to the
  bare form changes nothing, because rejection precedes the model.
- Correctly namespaced, the model called Workflow and then **ended its turn** with *"I'll report
  back when it completes"*, `stop_reason:"end_turn"`, no `TaskOutput` anywhere → partial
  `.gad/generation-0/`, no commit. This reproduces the "gen 0 death" that
  `claude-relay/relay/gadkit.py`'s `command()` docstring documents. CONFIRMED.
- Without `--dangerously-skip-permissions` in genuine non-auto permission mode, six tool calls
  including `Workflow` and `Skill(gad-kit:gad-run)` were **silently auto-denied**, exit **0**,
  `is_error:false`. A third exit-0 no-op path. Caveat: this machine's `~/.claude/settings.json`
  sets `"permissions":{"defaultMode":"auto"}` globally, which is NOT the out-of-box default — so on
  an unmodified install this is likely the *default* outcome of a tick.
- **claude-relay's mechanism is validated end-to-end.** Running its real `command()` argv produced
  a complete generation: `gen-0:` commits landed, `nextGen` advanced 0→1, `generations=[0]`, and the
  full artifact set including `reviews/verification.md` and `live-verification.md`. The
  explicit-`Workflow` + blocking-`TaskOutput` prompt is not merely better-behaved; it finishes.
- Incidental: the Workflow tool accepts `args` as a JSON-encoded **string** as well as a literal
  object, contrary to that docstring's stricter claim.

Because all three failure modes exit 0, `gad-cron-tick.sh:70`'s `echo 0 > "$STATE"` resets the
kill-switch on every no-op and `gad-fleet-tick.sh:147` records `lastStatus:"ok"` forever.

### B35 · HIGH (pre-existing) · `handoff.md` is not a blocker sentinel

`relay/gadkit.py:428-438` (`triage()` step 2) returns `Plan(kind="BLOCKED")` on the mere existence
of `.gad/generation-N/handoff.md`, and `snapshot()`/`outcome()` map `handoff_exists` → the `BLOCKED`
bucket → `NOTIFY_PARK` → `_park_and_wait()`. **That premise is false.**

Observed: a generation that committed successfully wrote `handoff.md` anyway, header verbatim
`## Status: COMMITTED (pending commit hash — see generations-index.json / BUILD_STATUS.md)`, and the
file is committed as part of the generation. `gad-kit/agents/consolidator.md` confirms the design —
only `:8` is the blocker case; `:57` (open questions), `:67` (operator action for metered live
seams, explicitly "Non-blocking"), `:76` (the ranked owner-decisions section) and `:88` (the
advisory opportunity scout) are all routine, non-blocking uses.

Failure scenario: it does not bite in the steady state (after success `nextGen` has advanced past
that directory), but it bites in exactly the case gad-kit's `IDEMPOTENT COMMIT` guard exists for —
the consolidator commits and dies before updating the index. Then `nextGen` still names that
generation, its `handoff.md` is present, and claude-relay parks a **committed, verified** generation
as BLOCKED and pages the operator. The A7 fix's `OR handoff_gen == next_gen` exception re-admits it.

Fix: a handoff blocks only if that generation is genuinely uncommitted — absent from `generations[]`
AND with no `gen-<N>:` commit in history. Treat the `## Status:` line as corroboration only, never
as the primary signal (it is model-written prose). Every consumer of handoff presence must agree:
`triage()` step 2, `find_uncommitted_handoff()`, the A7 exception, `snapshot()`/`outcome()`.

### A1/A2/A2b were dead code — and the CLI already emits a structured limit signal

**CONFIRMED empirically.** `command()` invokes the child with `--output-format stream-json --verbose`,
which is NDJSON: one compact JSON envelope per physical stdout line. `runner.py` puts *raw* lines
into `RunResult.tail`, and `detector.py` matched `^\s*RESULT\s*:` against those raw lines. A real
invocation produced **zero** lines beginning with `RESULT:` — every line starts with `{`, and the
model's instructed `RESULT: <status>` text exists only as a JSON-escaped substring inside an
`assistant` envelope. So `tail_has_workflow_limit_signature()` could never fire in production, and
the entire A1 → A2 → A2b chain across two fix rounds was inert. The tests encoded the false premise
(`tail = ["RESULT: LIMIT-SUSPECTED"]`), which is why a green gate never caught it.

**This was my error, twice, and it was avoidable:** an earlier reviewer had already established that
substring matching works *because* the text is embedded as JSON string content — and I then specified
a line-anchored match, which breaks under exactly the property that reviewer described.

**The better mechanism, which existed all along.** The CLI emits a first-class structured event on
the same stream:

```json
{"type":"rate_limit_event","rate_limit_info":{
  "status":"allowed_warning","resetsAt":1785290400,
  "rateLimitType":"seven_day","utilization":0.76,
  "isUsingOverage":false,"surpassedThreshold":0.75}}
```

Status, real reset epoch, limit type, and utilisation (a 0–1 fraction, **not** a percent) — machine-
readable, emitted by the platform. This is structured data, not model prose, so trusting it does not
weaken Invariant #2; the invariant's "stdout is a backstop only" framing assumed stdout was prose,
and it isn't. Every round of substring heuristics was reinventing a worse version of this.

Envelope types observed in one trivial run: `system` (`hook_started`, `hook_response`, `init`),
`assistant`, `rate_limit_event`, `result` (`success`; keys include `api_error_status`, `is_error`,
`num_turns`, `modelUsage`, `duration_ms`).

**Caution for whoever extends this:** only `status:"allowed_warning"` and
`rateLimitType:"seven_day"` were observed. The values emitted when a request is actually *blocked*,
and the five-hour variant's spelling, are UNKNOWN. Treat an unrecognised status as potentially
limiting, never hard-code an exhaustive enum, and guess toward rotate-and-cool rather than
keep-spending.

**Bonus, deferred:** the `result` envelope's `modelUsage` + `api_error_status` are exactly the
structured token-cost fields DESIGN.md §4 says Phase 2 batching needs ("derive per-unit cost from
the structured token-usage fields Claude Code emits in `--output-format stream-json` — immune to
window semantics; not prose"). The data is confirmed present. The calibration work is not blocked on
discovery any more, only on someone doing it.

### B13's commit is unchecked — a failed commit destroys the operator's answer

**CONFIRMED, live-reproduced.** `relay/gadkit.py:1313-1322` checks `git add`'s return code but not
`git commit`'s, and returns `found=True` regardless. With a rejecting pre-commit hook (and,
separately, with no git identity configured): the JSON is written, `add` succeeds, `commit` fails,
the function reports success, and the tree is left dirty with the index staged. The next `triage()` —
the loop runs continuously — sees an unmoved HEAD plus a `.gad/` signal, judges the dirt attributable
to itself, and stashes it. The file reverts to `"status": "open"`, the resolution is gone, **and**
triage proposes a spurious `/gad-generation` restart. Exactly what the commit was added to prevent,
via an ordinary operator condition rather than an exotic one.

The *scope* half of B13 is correct and should be preserved: `git commit -- <path>` provably does not
sweep other staged files (verified with an unrelated staged file, which stayed staged and untouched).
